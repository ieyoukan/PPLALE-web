# ゲーム画面の読み込み改善

## 対戦中のパネル読み込み

メニュー・ログ・カード情報などのサイドパネル、初期手札交換、ランチパッド内の画面には、それぞれ局所的な `Suspense` を置く。表示時の遅延読み込みがルーム全体の境界まで伝わると盤面が非表示になり、茶色の背景だけが見えるため、読み込み待ちは各パネル内に限定する。盤面と対戦状態は維持する。

`e2e/board-overlay-loading.spec.mjs` ではルーム通信を模擬し、追加スクリプトの読み込みを遅らせても、メニュー・手札交換の表示前後で同じ盤面が各描画フレームに残ることを検証する。

## 2026-10-22：開始前の準備とルーム通信

- ゲームメニュー用の文字を専用フォントサブセットに集約。通常の未ログイン画面では6ファイル、約180KB。任意のユーザー名に必要な文字も64文字単位の追加ファイルで保持する。
- 対戦用CSSから設定画面のCSSを分離し、タブの自動プリフェッチを止める。盤面・3Dダイス・マリガン・保存データの復元コードは開始前に読み込む。
- 対応ブラウザでは横向きステージの初期配置をCSSでも計算する。JavaScriptの起動まで全体を隠していた待ちをなくし、起動後も同じ位置・寸法を維持する。非対応ブラウザは従来のJavaScriptによる配置を使う。JavaScriptの取得を止めた5サイズと、画面回転を含めて検証する。
- `pnpm run game:assets`（`predev` / `prebuild`でも実行）がカード212枚のAVIF / WebPと圧縮したメニュー背景を生成する。原画は変更せず、生成物はGit管理しない。カードは幅640px、AVIF品質50 / WebP品質82。手札・盤面・拡大表示で同じハッシュ付きURLを使う。AVIFに対応しない環境はWebPを準備する。
- CPU開始前、ルームの「準備OK」送信前、フリーマッチの検索開始前に、使用可能な公開カードプールと全トークンを4並列で先読みしてデコードを待つ。相手の非公開デッキは要求しない。ルーム待機中にも先読みし、直接URL・再開時は盤面をマウントする前に準備する。失敗時は開始せず再試行できる。
- CPU / 形勢評価Workerは起動完了を待って盤面へ渡す。「さいきょう」の配信モデルも開始前に取得する。通常CPUではモデルを取得しない。
- ルームのWebSocketは2KB以上のメッセージを `permessage-deflate` で圧縮する。圧縮レベル3・同時処理4・コンテキストを持ち越さない設定とし、非対応クライアントとも接続できる。盤面の非公開情報の除去、コマンドの順序、保存の耐久性は従来どおり。

同じ伏せ情報を含む盤面のローカル通信テストでは約15.4KBから約1.5KBへ削減した。これは転送量の比較であり、操作遅延が90%短縮したという測定ではない。回線の往復時間やサーバーの保存処理は残る。

検証コマンド：`pnpm run test:fonts`、`pnpm run test:game-assets`、`pnpm run test:room-server`、`pnpm run build`。ブラウザでは `game-preparation`、`room-latency`、`room-match`、`font-subsets`、`screen-fit` の準備画面、`game-match` のCPU進行を検証する。対戦用のブラウザ検証には `NEXT_PUBLIC_ROOM_SERVER_URL` を設定したビルドと `PPLALE_ROOM_TEST_URL` が必要。

以下は以前の構成・測定記録であり、上記の先読み方式や外部CSS配信とは異なる。

2026-10-16 に、下記の設定・読み込み方法を現行コードと照合した。測定値は過去の記録で、今回再測定した値ではない。検証結果は [検証記録](../verification.md)。

## 2026-10-04 の変更記録

- カードの `unoptimized` を外し、盤面・手札・拡大表示ごとに `sizes` を指定する。高解像度画面用に160・192pxの画像候補も追加する。
- 背景ロゴはSVGのままHTMLの画像として出力する。遅延読み込みをせず、先頭の画像には `fetchPriority="high"` を指定する。
- Firebaseアプリの初期化とFirestoreを分ける。認証SDKは初期描画後、保存済みデッキの取得処理はログイン後に読み込む。
- CPUの表示名と探索処理を分ける。WorkerはCPU対戦開始後に作成し、Workerを使えない場合の探索処理も動的に読み込む。
- 保存データ検証用のZodは、保存データが存在するときに読み込む。設定値の読み出しはカードスキーマから独立させる。
- メニュー・履歴・カード詳細・スキル・除外カード一覧・初期手札交換は、表示時に読み込む。
- Pandaのスタイルは利用するサイトページで読み込む。ゲーム画面には共有リセットとゲーム用CSSを読み込む。使用されていない旧UIのセレクターも削除する。
- Next.js の `experimental.inlineCss` を有効にする。本番ビルドのHTMLへCSSを埋め込む設定で、開発モードには適用されない。全ページ共通の実験的な設定で、ページ別には指定できない。埋め込んだCSSは独立してキャッシュされず、事前生成ページへのクライアント遷移では外部CSSを使う場合がある（インストール済みNext.jsの `node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/inlineCss.md`）。
- 相手の手札に `role="group"`、数字のおはじきに `role="img"` を付ける。ルール設定と開始ボタンの文字色を濃くする。
- 固定のホーム用canonicalを共通レイアウトから外す。ホームは `/`、ゲームは `/game/` をMetadata APIで指定する。
- アプリのTypeScriptターゲットをES2022にする。

## 残る監査項目

Next.js本体の機能判定付き互換コードは引き続き含まれるため、「以前のJavaScript」の警告は残り得る。必要なReact・Next.jsの起動処理や、操作前の読み込み済みコードも未使用JS判定に含まれる。LCP・TBTの時間やLighthouse全体のスコアは、デプロイ後に同じ端末・通信条件で再計測する必要がある。
