# ゲーム画面の読み込み改善

## 2026-10-28：ルームの描画と画像準備

- 待機中は公開ルールに含まれるカードを低優先度の `fetch` で取得し、圧縮されたままHTTPキャッシュへ置く。全カードを `Image.decode()` で展開しない。カード画像のURL・解像度・圧縮設定は共用の生成物を使う。
- 対戦・観戦へ入る直前は、サーバーから届いた局面で識別できるカードだけをデコードしてからカメラを動かす。山札などの `hidden` は対象にしない。準備のキーは試合・席・ルールに固定し、その後のドローや公開で盤面を再マウントしない。CPU対戦など既存の開始ゲートは従来どおり準備する。
- `PlazaRoom` へ先読みを集約し、`PlazaTable` の重複を削除する。四並列の上限、共有する完了キャッシュ、失敗時の再試行、途中退出による待ち行列の中止を保持する。
- 天板のSVG木目はそのまま使い、天板だけを `translateZ(0)`・`will-change: transform` で合成用にキャッシュする。床全体や各カードへ一律のレイヤー指定は付けない。机・床の形とカメラの時間は維持する。
- 静的な机・床と待機盤面を `memo` で共用する。デッキ候補はルール値でキャッシュし、同じルールのWebSocket更新でランダムデッキ候補の検証を繰り返さない。

画像準備の中断・再試行は `tests/room-warm-assets.test.mjs`、伏せ情報を除外するカード選択は `tests/game-assets.test.mjs`、圧縮された先読み・表示前のデコード待ち・キャッシュ再利用・後から公開されたカードでの盤面維持は `e2e/room-asset-warming.spec.mjs` で確認する。

計測は `scripts/measure-room-rendering.mjs` を本番ビルドの `next start` に向けて行う。1280×800・390×844を各3回、CPUを4倍に遅くし、同じ模擬ルーム・同じ局面を送る。新しいブラウザを毎回起動し、Service Workerは無効にする。実回線や本番サーバーの遅延は比較に含めない。描画スレッドの `RasterTask` は合計時間であり、画面更新の間隔は `requestAnimationFrame` のコールバック間隔で、実際に提示されたFPSとは異なる。

同一マシン・本番ビルドでの3回の中央値（2026-10-28）。変更前は `898253f`、変更後は `679c6b9` と本節の軽量化差分。JSのgzip換算量は556.2KB→556.5KBでほぼ同じ。比較する主な効果は実行時の画像展開・再描画処理。以下はローカルの模擬通信・CPU低速化の結果で、本番端末のFPSや通信遅延の改善率ではない。

| 条件・計測区間 | 変更前 | 変更後 | 増減 |

| 1280px・開始〜カメラ完了のメインスレッド | 484.7ms | 432.9ms | -10.7% |
| 1280px・同区間のRasterTask合計 | 890.7ms | 748.9ms | -15.9% |
| 390px・開始〜カメラ完了のメインスレッド | 539.8ms | 486.0ms | -10.0% |

生の計測は [変更前](room-rendering-2026-10-28-before.json)・[変更後](room-rendering-2026-10-28-after.json)。起動側の資源スナップショットはnetworkidle時点で、以前のデコード待ちの先読みがまだ続く場合があるため、初期のresourceBytesだけで総転送量を比較しない。

## 対戦中のパネル読み込み

メニュー・ログ・カード情報などのサイドパネル、初期手札交換、ランチパッド内の画面には、それぞれ局所的な `Suspense` を置く。表示時の遅延読み込みがルーム全体の境界まで伝わると盤面が非表示になり、茶色の背景だけが見えるため、読み込み待ちは各パネル内に限定する。盤面と対戦状態は維持する。

`e2e/board-overlay-loading.spec.mjs` ではルーム通信を模擬し、追加スクリプトの読み込みを遅らせても、メニュー・手札交換の表示前後で同じ盤面が各描画フレームに残ることを検証する。

## 2026-10-22：開始前の準備とルーム通信

- ゲームメニュー用の文字を専用フォントサブセットに集約。通常の未ログイン画面では6ファイル、約180KB。任意のユーザー名に必要な文字も64文字単位の追加ファイルで保持する。
- 対戦用CSSから設定画面のCSSを分離し、タブの自動プリフェッチを止める。盤面・3Dダイス・マリガン・保存データの復元コードは開始前に読み込む。
- 対応ブラウザでは横向きステージの初期配置をCSSでも計算する。JavaScriptの起動まで全体を隠していた待ちをなくし、起動後も同じ位置・寸法を維持する。非対応ブラウザは従来のJavaScriptによる配置を使う。JavaScriptの取得を止めた5サイズと、画面回転を含めて検証する。
- `pnpm run game:assets`（`predev` / `prebuild`でも実行）がカード212枚のAVIF / WebPと圧縮したメニュー背景を生成する。原画は変更せず、生成物はGit管理しない。カードは幅640px、AVIF品質50（effort 3）/ WebP品質82。手札・盤面・拡大表示で同じハッシュ付きURLを使う。AVIFに対応しない環境はWebPを準備する。生成物は内容ハッシュ付きで `.next/cache/pplale-assets` に保存し、変更のないカードは再エンコードしない。
- CPU開始前、ルームの「準備OK」送信前、フリーマッチの検索開始前に、使用可能な公開カードプールと全トークンを4並列で先読みしてデコードを待つ。相手の非公開デッキは要求しない。集まれるルームの待機中の先読みと開始前のデコードは、上の2026-10-28の方式を使う。直接URL・再開時も表示するカードを準備してから盤面をマウントする。失敗時は開始せず再試行できる。
- CPU / 形勢評価Workerは起動完了を待って盤面へ渡す。「さいきょう」の配信モデルも開始前に取得する。通常CPUではモデルを取得しない。
- ルームのWebSocketは2KB以上のメッセージを `permessage-deflate` で圧縮する。圧縮レベル3・同時処理4・コンテキストを持ち越さない設定とし、非対応クライアントとも接続できる。盤面の非公開情報の除去、コマンドの順序、保存の耐久性は従来どおり。

同じ伏せ情報を含む盤面のローカル通信テストでは約15.4KBから約1.5KBへ削減した。これは転送量の比較であり、操作遅延が90%短縮したという測定ではない。回線の往復時間やサーバーの保存処理は残る。

検証コマンド：`pnpm run test:fonts`、`pnpm run test:game-assets`、`pnpm run test:room-server`、`pnpm run build`。ブラウザでは `game-preparation`、`room-latency`、`room-match`、`font-subsets`、`screen-fit` の準備画面、`game-match` のCPU進行を検証する。対戦用のブラウザ検証には `NEXT_PUBLIC_ROOM_SERVER_URL` を設定したビルドと `PPLALE_ROOM_TEST_URL` が必要。

## 2026-10-04 の変更記録

- カードの `unoptimized` を外し、盤面・手札・拡大表示ごとに `sizes` を指定する。高解像度画面用に160・192pxの画像候補も追加する。
- 背景ロゴはSVGのままHTMLの画像として出力する。遅延読み込みをせず、先頭の画像には `fetchPriority="high"` を指定する。
- Firebaseアプリの初期化とFirestoreを分ける。認証SDKは初期描画後、保存済みデッキの取得処理はログイン後に読み込む。
- CPUの表示名と探索処理を分ける。WorkerはCPU対戦開始後に作成し、Workerを使えない場合の探索処理も動的に読み込む。
- 保存データ検証用のZodは、保存データが存在するときに読み込む。設定値の読み出しはカードスキーマから独立させる。
- メニュー・履歴・カード詳細・スキル・除外カード一覧・初期手札交換は、表示時に読み込む。
- Pandaのスタイルは利用するサイトページで読み込む。ゲーム画面には共有リセットとゲーム用CSSを読み込む。使用されていない旧UIのセレクターも削除する。
- Next.js の `experimental.inlineCss` を有効にする。本番ビルドのHTMLへCSSを埋め込む設定で、開発モードには適用されない。全ページ共通の実験的な設定で、ページ別には指定できない。埋め込んだCSSは独立してキャッシュされず、事前生成ページへのクライアント遷移では外部CSSを使う場合がある（インストール済みNext.jsの `node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/inlineCss.md`）。
- 相手の手札に `role="group"`、数字のおはじきに `role="img"` を付ける。ルール設定と開始ボタンの文字色を濃くする。
- 固定のホーム用canonicalを共通レイアウトから外す。ホームは `/`、ゲームは `/game/` をMetadata APIで指定する。
- アプリのTypeScriptターゲットをES2022にする。

## サイコロの静止中の描画（2026-10-28）

`openingDieScene.ts` は値・回転状態が変わらずリサイズもないとき、WebGL描画とメッシュの接地計算を繰り返さない。回転中は従来どおり描き、止まった時点とリサイズで描き直す。Three.jsが廃止した `PCFSoftShadowMap` は、実際の代替先と同じ `PCFShadowMap` を明示する。`e2e/display-and-die-regressions.spec.mjs` で静止中の描画回数と回転時の再開を検証する。

通知音の `AudioContext` は [Chromeの自動再生ポリシー](https://developer.chrome.com/blog/autoplay/#web_audio) に合わせ、有効なユーザー操作中だけ生成・再開する。疑似イベントや操作前の呼び出しでは生成しない。
