# トップページの初期処理

2026-10-21。ユーザーのLighthouse 13.5.0レポートではデスクトップ76点、FCP 0.6秒、LCP 1.2秒、TBT 440ms、CLS 0。LCP画像の優先度不足と、未使用JavaScript約125KiBが報告された。

## 変更

- ロゴは初期HTMLに `loading="eager"`・`fetchPriority="high"` を出す。背景とメニュー画像に付いていた複数のpreloadは外し、ロゴの取得を優先する。
- ヒーローをServer Componentに戻し、ホバー・押下の動きをCSSへ移す。
- ピックアップの山札は初期HTMLに描画する。抽選時に初めてカード全データ・Zod・カード詳細・Framer Motionを読み込み、開いたカードの演出は維持する。読込中の連打を防ぎ、失敗時は再試行できる。
- 認証SDKは `useAuth` の利用画面が表示された時点で開始する。一度開始した監視はルートのProvider内で保ち、ホームに戻っても別タブのアカウント切替を監視し続ける。
- ホーム内のゲーム・構築・説明リンクは表示時の先読みを止める。フォント・配色・配置・カード効果には変更を加えない。

## サイトのページのLCP（2026-11-06）

Lighthouse（モバイル）で、ぷぷりえーるとはのLCPが本番で13.4秒（推定方式）・19.2秒（実際に回線とCPUを遅くした `--throttling-method=devtools`）だった。原因と対応：

- **本の1ページ目**（LCPの画像）が `loading="lazy"`・`unoptimized` で、元の大きさの画像を後から読んでいた。1ページ目だけ `preload`・`fetchPriority="high"` にし、表示幅に合わせて最適化した画像を配信する。サムネイルも `sizes="96px"` で縮小（約2.9MB減）。拡大表示だけは文字を読むため元の画像のまま。
- **ルール全文のフォント**：SEOのためにルール・裁定集の全文を常に表示すると、本文の漢字に合わせてまれな漢字のフォント分割が135本（約2.2MB）読まれた。本文用の書体「PPLALE Rules」（Zen Maru Gothicの500・700、共通の分割にない272字）を1本ずつ生成し（`scripts/generate-site-fonts.mjs` → `src/app/generated/rules-fonts.css`）、`RulesDoc` からだけ読み込む。共通のフォントCSSは分割しないので大きさは変わらない（約112KB、gzip約14KB）。
- **トップの紹介動画**：スマホでは最初の画面に入るため、約6MBの読み込みがヒーローのイラストと回線を取り合っていた。`IntroMovie` は `load` の後、ブラウザが空いてから近づいたときに読み込む。
- ヒーローのイラストとコミュニティのワールドの絵に `preload` を付ける。

手元の本番ビルド（`next start`）での結果（devtools方式）：トップ LCP 1.8秒、ぷぷりえーるとは LCP 2.1秒（フォント28本・583KB、ページ全体1.2MB）。残る遅れは、描画を止めるCSSのファイル（ぷぷりえーるとはで6本）。`experimental.inlineCss` で埋め込めるが、実験的機能でサイト全体（ゲーム画面を含む）に効き、再訪問時にCSSをキャッシュできず、RSCの中身とCSSが二重に送られるため採用していない。推定方式（Lighthouseの既定）は、画像の表示がJavaScriptの実行を待つものとして3秒前後の遅れを加えるので、実際の遅れは devtools 方式で確認する。
