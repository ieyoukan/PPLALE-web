# プロフィールとフレンド

## 画面と導線

フレンド一覧はアイコン・名前・現在地を表示し、ユーザーを押すとプロフィールを開く。プロフィールが届く前の「プレイヤー」という仮名の行は作らず、読み込み中として待つ。オフラインでも取得済みの正しい名前を使い、プロフィールが未作成・削除済みなら架空の行を出さない。招待依頼とフレンド解除はプロフィールにまとめ、一覧に「リクエストインバイト」や「…」の操作を置かない。解除はプロフィール内で確認してから実行する。

- `/game/profile/`: 自分の名前（12文字）、カードのアイコン、ひとこと（80文字）を保存。初期コメントは「よろしくお願いします！」。Googleの写真やメールアドレスは公開プロフィールに含めない。
- 自分のアイコン・在室者一覧・現在地のメンバー一覧は、ゲストでも自分のプロフィールを開ける。未ログインなら共通の `GuestSignInPrompt` でログインを要求する。認証の失敗・キャンセルはその場で再試行でき、ルームは退出しない。他のゲストには公開プロフィールへのリンクを付けない。
- 通知タブにはブラウザ通知のベル切り替えを置かない。ブラウザ通知の許可・停止は設定の `PushToggle` にまとめる。
- ログイン後、公開プロフィールが未作成なら初回設定ダイアログを表示する。名前は空欄から入力し、保存すると元の画面で続けられる。自分のプロフィール画面では同じ設定をページ内で行う。保存済みのユーザーには再表示せず、取得失敗時は再読み込みを案内する。
- `/game/profile/?id=...`: 他の人の公開プロフィールとフレンド申請。左上のボタンでソーシャルへ戻る。フレンドがいまいるルームをワールドのカードのように表示し、選ぶと参加（募集中）・観戦（対戦中）できる。
- 共有用の短いURLは `/u/{uid}`（`next.config.ts` で `/game/profile/?id=` へ転送。ゲーム中はアドレス欄がルームのURLなので、共有はボタンから行う）。プロフィールの名前・ひとことの直下（スクロールせずに見える位置）に、URLのコピー・Discordに貼るメッセージのコピー・Xへのポスト・端末の共有（対応ブラウザのみ）を並べる。自分のプロフィールでは強調色にする。フレンドがいないソーシャル画面にも同じ共有ボタンを出す。
- ログインしていない人が他の人のプロフィールを開くと、相手と自分（ルーム内のゲストのアイコン。ルーム外なら空の丸）のアイコンの間にハートを置き、「ログインしてフレンドになる」を表示する。押すとGoogleログインし、初回ならプロフィール設定のあとに、そのまま1回だけフレンド申請を送る。フレンド以外には現在地を「フレンド限定」と表示し、オンラインかどうかも伝えない。
- 名前検索: ソーシャル画面と通知画面の検索欄（ログイン中のみ）。名前の一部で探せて、全角・半角、大文字・小文字、カタカナ・ひらがなの違いと空白は無視する。プロフィールのURL・IDを貼るとそのプロフィールへのリンクを出す。結果は自分を除いて20件まで。設定はなく、すべてのプロフィールが検索の対象になる。
- プロフィールでは、保存済みのデッキから3つまで選んで掲載できる。デッキ自体は共有URLで単体取得できるが、保存済みデッキの一覧を取得できるのは所有者だけ。プロフィールにはIDだけを保存する。プロフィールに掲載していないデッキでも、共有URLを知っていれば単体取得できる。
- 通知へはランチパッドのベルのタブから入る。ソーシャル画面には通知のアイコンを置かない（二重にしない）。
- `/game/social/`: VRChatの「フレンドの現在地」のように、フレンドを募集中のルームごとにまとめて並べる。ルームのカードから参加・観戦でき、フレンド解除もここで行う。ログインして観戦しているフレンドも、そのルームに並ぶ。どのルームにもいないフレンドは見出しを付けずに一覧にする。
- `/game/notifications/`: 通知。届いた申請の承認・見送り、送った申請の取消、名前・プロフィールのリンクでのユーザー検索。
- ルームのホストが「フレンドに対戦を募集する」を押すと公開。空席なら「参加」、観戦可能な対戦中なら「観戦」へ入る。プロフィールのUIDとサーバーが認証したホストUIDが一致し、実際に接続している場合だけ募集として扱う。
- ルームIDを知っている人が参加できる既存ルールはそのまま。募集先の一覧を見られるのは承認済みフレンドだけ。

## ランチパッドの自分表示と称号（2026-10-29）

ランチパッド最上段のアイコン・公開ユーザー名は自分のプロフィールへの共通入口にする。通常サイズのすべてのタブで表示し、ゲストも押せる。拡大画面では最上段を表示せず、縮小すると再び表示する。ログイン／ログアウトの切り替え中に前のアカウントの名前・アイコンを表示しない。ログイン済みのアイコンはプロフィール保存イベントに追従し、ゲストのアイコンはルーム内と同じ識別方法を使う。

将来の称号表示に備え、`components/shared/player/PlayerIdentity.tsx` にアイコン・名前・任意の称号行をまとめる。称号がない場合は空の行や仮の称号を出さない。現時点ではプロフィールの保存形式を変えず、称号の獲得・選択は未実装。実装時には付与条件と正本を決め、実績による称号を本人が任意に書き換えられないよう保存・検証を設計する。

## Firebaseの保存対象

`profiles/{uid}`: displayName, iconCardId, comment, decks（公開するデッキのID、3つまで）, searchable, nameGrams, createdAt, updatedAt。単体の公開読み取り、所有者の書き込みだけ許可。プロフィール一覧の全件取得・クライアントからの検索クエリは許可しない。

名前検索: `nameGrams` は正規化した名前（`src/lib/game/profileSearch.ts` の `foldName`）の部分文字列すべて（12文字で最大78個）。検索は `GET /api/profiles/search/?q=` がID tokenをFirebase Authの `accounts:lookup` で確認し（`firebase-admin/auth` はESM専用の依存をrequireするためVercelで読み込めない）、Admin SDKで `array-contains` を1回だけ実行する（ページ送りなし、20件まで）。返すのは公開項目（名前・ひとこと・アイコン）だけで、所有者が書く `nameGrams` を信用せず、実際の名前に検索語が含まれるものだけを返す。検索導入前のプロフィール（と、一時期あった非表示設定で `searchable: false` のもの）は、本人がログインしたときに検索用の2項目だけを書き足す（ほかの項目は書き換えない）。Admin SDKの認証情報はVercelの `FIREBASE_PROJECT_ID`・`FIREBASE_CLIENT_EMAIL`・`FIREBASE_PRIVATE_KEY`（デッキのOGP画像と共通）。

`friendships/{sortedUidA~sortedUidB}`: members, requestedBy, status, createdAt, acceptedAt。申請側はpendingだけ作成でき、承認は相手側だけ。メンバーの差し替えや他人のフレンド一覧の読み取りは禁止。双方どちらからでも削除でき、削除後は相手の募集を読めない。

`recruitments/{uid}`: roomId, updatedAt。所有者が明示的に公開/取り下げする。承認済みフレンドだけ読み取り可能。古い募集が残っても、実ルームとホストの接続をRedisで確認して表示するため、解散したルームへ誘導しない。

`watching/{uid}`: roomId, updatedAt。ログイン中に、フレンドが見つけられる集まれるルーム（パブリック・フレンド・フレンド＋）に在室している間と、2人用ルームを観戦画面で見ている間だけ書き、1分ごとに更新、離れると削除する（インバイト系のルームでは書かない）。読み取りは承認済みフレンドだけ。3分以上更新がないもの、入れないルーム、観戦できる対戦中でなくなった2人用ルームは表示しない。コレクション名は既存ルールのまま（公開済みのルールを変えずに使える）。観戦者はサーバー上では人数だけで、誰が見ているかはサーバーに渡さない。

常時のオンライン通知はFirebaseに書かない（在室・観戦中の更新はその画面を開いている間だけ）。ソーシャル画面を開いている間だけ必要なドキュメントを購読する。ルーム状態は既存サーバーに15秒おきにまとめて1回確認し（`POST /rooms/lookup`。サーバーは、ログインした本人が入れるルームだけを返す）、非表示タブでは確認を止める。初期実装のフレンド・申請一覧は合計100件まで。大量利用向けの検索・ページ分けは別途追加する。

外部の有料DBやCloud Functionsは追加しない。ただしFirestoreは既存プロジェクトの無料枠と料金プランに従う。無制限の無料利用を保証する仕組みではない。

## 観戦とリプレイ

自動マッチングと専用の対戦一覧は2026-10-29に廃止した。過去の対戦履歴・リプレイは引き続き閲覧できる。ルームはランチパッドの「ルーム」とソーシャルから探す。公開盤面による形勢表示はルーム対戦でも共用し、手札や山札の順序を推測するために非公開情報を使わない。

## 認証と公開

公開用の名前は保存したプロフィールから取得し、Googleアカウントの名前・メール・写真へフォールバックしない。プロフィール取得中は安全な仮名を表示し、ルーム作成・参加は読み込み完了を待つ。初回プロフィールにもGoogle名を自動入力しない。CPU対戦の勝敗表示も同じ公開プロフィールを使う。

ログイン中の対戦名はプロフィール名に固定し、変更はプロフィール画面から行う。ゲスト名だけは入力・専用保存を許可し、旧来のアカウント共通の名前キャッシュは読み込まない。共有デッキには現在のプロフィール名を作成者として表示する。対戦一覧、ルーム、履歴・公開リプレイは認証済みのプロフィールUIDから現在の名前を解決し、取得失敗・未作成の場合は「プレイヤー」とする（保存された旧名には戻さない）。サーバーの公開名キャッシュは更新間隔60秒、最大2000件、取得の同時実行は8件。期限後は確認済みの公開名を表示しながら再取得し、一時的な取得失敗ではその名前を保持して5秒後から再試行する。プロフィール未作成・削除（404）では仮名に戻す。コマンドの送受信・演出はプロフィール取得を待たない。過去の記録は保存時のハッシュを検証した後、配信用コピーの名前とログ先頭のプレイヤー名を解決する。原本・カード名・デッキ名・対戦局面は変更しない。配信の `publicNamesResolved: true` はハッシュが原本に対応することを示す。古い記録にプロフィールUIDがなければ関連付けはできない。

プロフィールURLなどに含むFirebase UIDは公開用の識別子であり、メールアドレスやログイン用の秘密ではない。ゲームサーバーには認証のためID tokenを送るが、対戦相手・観戦者への応答にtokenやGoogleプロフィールを含めない。ログイン中はサーバーでも提出された別名を使わず、認証済みUIDの公開プロフィール名を採用する。ゲストは名前欄の値を使う。フルーツ・プレイアブル・盤面などの対戦情報も公開範囲に含まれる。

ユーザーが変わるとプロフィール編集・ソーシャル画面・取得済みのフレンド情報を破棄する。Firebase ID tokenとFirestoreルールで所有者を確認し、ゲームサーバーに送るプロフィールUIDは認証済みのUIDからだけ設定する。

Firestoreルールは `firebase.json` から `firebase deploy --only firestore:rules --project pplale-6cca0` で公開する。管理者のCLIログインが必要。既存のデッキ共有ルールを維持したうえで新しいコレクションだけ追加する。

ゲストにはランチパッドのホームと対戦後の結果画面で、既存キャラクターと「フレンドと、また遊ぼう」の短い案内・ログインボタンを表示する。Googleログインは本人がボタンを押したときだけ開始し、認証の確認中・ログイン済みには案内を重ねない。ログイン後は既存の初回プロフィール作成へ進む。対戦中の強制表示や操作制限は加えず、公開プロフィール・フレンド・デッキ共有の利用へ誘導する。ルームの対戦中は名前の横に席と同じ公開プロフィール／ゲストの丸いアイコンを表示し、CPUは共通のCPUアイコンで区別する。プロフィール取得中・失敗時もアイコンの代替を出し、対戦の進行を待たせない。

## ローカル検証

```
pnpm dlx firebase-tools@15.34.0 emulators:start --only firestore,auth --project demo-pplale-social
PPLALE_FIREBASE_RULES_TEST=1 node --test tests/social-rules.test.mjs
```

ブラウザの統合テストは `NEXT_PUBLIC_FIREBASE_EMULATORS=true` で起動した分離プレビューを利用する。認証とFirestoreの接続先はローカルに固定し、プロジェクトを `demo-pplale-social` に切り替える。本番環境ではこの変数を設定しない。

## 集まれるルームとフレンド

ゲームの起動時に入るルーム（[設計](social-rooms-design.md)、[サーバー](../services/room-server/README.md) の「集まれるルーム」）では、募集ボタンを使わずにフレンドの現在地を出す。

- パブリック・フレンド・フレンド＋のルームにいるログイン中のフレンドは、ソーシャル画面でそのルームのカード（ルーム名・公開範囲・人数）にまとまる。カードを選ぶと、今の画面のまま入室を確かめ、入れたらそのルームへ移る。入れないルーム（作成者のフレンドではないフレンドルームなど）はサーバーが返さないので表示されない。
- ソーシャル画面では、ルームカードと届いた招待をフルーツ環境・拡張プレイアブル・1ターンの時間で絞り込める。ルームカードの画像には共有リンクのOGPと同じ、ルール別のサムネイルを使う。ルーム外のフレンド表示は絞り込まない。
- インバイト・インバイト＋のルームは、ソーシャルのルーム一覧には表示しない。フレンドのプロフィールに「リクエストインバイト」があり、押すとフレンドがいるルームの招待できる人（インバイトはオーナー、インバイト＋は在室者）の盤面に届く。ルームの有無・名前・IDは返さない。許可されると名指しで入れるようになり、プッシュ通知とソーシャル画面の「招待が届いています」で知らせる。
- ルームの「さそう」から、ログイン中のフレンドを名指しで招待できる。サーバーが本人のID tokenでフレンド関係をFirestoreから確かめてから通知する（`POST /rooms/{id}/invite`）。インバイト系のルームでは、リンクを知らないそのフレンドも入れるようになる。ほかのルームでは入室条件を変えない（パブリック・フレンド＋ではもともと入れる。フレンドのルームでは作った人だけが、自分のフレンドを招待できる）。
- ルームのリンクをDiscordなどに貼ると（チャットアプリのプレビュー取得のときだけルームサーバーに尋ねる）、ルール別の画像（`/api/og/room/`。ロゴ・ゲームのキャラクター・使えるフルーツ・拡張プレイアブル・1ターンの時間）と、リンクで入れる範囲の名前・公開範囲・人数を表示する。招待の値（`?invite=`）は画像・タイトル・説明・`og:url` に含めない。招待の値がないインバイト系のリンク、フレンド系のルーム、存在しないIDは共通の文言と画像にする。
- 2人用ルーム（以前のルームと廃止前のフリーマッチ）の募集・観戦の表示は従来どおり。

ソーシャルの3人アイコンはタブにだけ表示する。「フレンドの現在地」は左寄せの本文書体のサブタイトルとし、人数も簡素な文字で添える。

### プロフィールの現在地

- プロフィールの右上に現在地を表示する。入室できるルームにはサムネイル・ルーム名と専用SVG付きの「入る」を表示する。
- `POST /rooms/location { to }` はID tokenで本人を確認し、自分または承認済みフレンドに限って応答する。ルームサーバー上の接続を確認し、未接続・確認失敗・現在地を確認できない相手は「オフライン」と表示し、古い入室・依頼操作を残さない。
- 入室できないインバイト・インバイト＋は `private` と公開範囲の種類だけを返す。プロフィールには「プライベートルーム」、その下に「インバイト」または「インバイト＋」を表示し、部屋ID・部屋名・ルール・在室者・招待トークンを返さない。入室条件を満たさないフレンド系ルームも同様に伏せる。名前付き招待などで入室権限を持つ場合は、インバイト系でも `room` を返して「入る」を表示する。招待トークンは返さない。
- 現在地はプロフィールを開いている間だけ15秒ごとに再確認する。非表示タブでは確認を止める。相手の現在地が `private` のときだけ、現在地の下に専用SVG付きの「リクエストインバイト」を表示する。別の操作として、承認済みフレンドのプロフィール本体には封筒SVG付きの「招待を送る」を置き、自分がいるルームへ招待する。現在の部屋で招待権限がない場合・相手が同室の場合は無効にする。送信後は「送信済み」と表示する。
