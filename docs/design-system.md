# ぷぷりえーるの配色・デザイン基準

## 原典

ユーザー指定の「お菓子争奪戦争ぷぷりえーる」ロゴ（`public/pupu_game.webp`）をサイトの配色の原典とする。キャラクターごとにUIの世界観を変えず、ロゴの桜色・クリーム・ココアブラウンを土台に揃える。

共通の色は `src/app/brand.css` のCSS変数を使う。Panda CSSでも `var(--brand-cocoa)` のように参照できる。新しいページや既存画面の改修時にもこの基準を使う。

| 用途 | 変数 | 色 |
| --- | --- | --- |
| ページの背景 | `--brand-cream` | `#fff8f0` |
| パネル・カード | `--brand-paper` | `#fffdf9` |
| 淡い桜色 | `--brand-blush` | `#f8e8e8` |
| ボタン・装飾 | `--brand-pink` | `#e8c8c8` |
| 枠・影の縁 | `--brand-pink-edge` | `#c8a8a8` |
| 葉っぱの緑 | `--brand-sage` | `#c8d888` |
| 星・お菓子の黄色 | `--brand-vanilla` | `#f5df97` |
| 小さな差し色 | `--brand-peach` | `#efb39d` |
| 見出し・輪郭 | `--brand-cocoa` | `#785858` |
| 本文・ボタンの文字 | `--brand-cocoa-deep` | `#634747` |
| 補助文 | `--brand-cocoa-soft` | `#7b5e58` |

ロゴの淡い色は面や装飾に使い、文字はココア色で読む。明るいピンクの文字をクリームや黄色の背景に載せない。通常の文字と主要な見出しは、実際の背景とのコントラスト比4.5:1以上を確保する。明るいボタンには濃い文字を使う。ゲームの淡いパネル・フォームはサイトのダークモードでも同じ配色を維持する。`GameStage` 内で文字・入力欄の背景のテーマ変数と `color-scheme: light` を設定し、サイト全体の `label`・`option` の色を持ち込まない。

## 背景

トップページのヒーローは、ユーザー指定の4人のイラスト `orig_mousepad.png` を `public/images/home/hero-friends.webp` に変換して使う（長辺2400px・WebP品質94）。4人の顔を切らずに全体を表示し、原画左上の花柄の余白へ `public/pupu_game.webp` のロゴを重ねる。ゲームなどへの3つの入口は画像の下へ置き、顔にボタンを重ねない。配置は `sections/HeroSection.tsx`・`HeroSection.module.css` で共用する。

ユーザー指定により、ロゴ配色に加えて黄色・オレンジの暖かい背景を採用する。紹介とカードピックアップは既存の `public/images/check-pattern.png` を使う100px周期のチェック柄、機能への入口は淡い黄色（`--brand-vanilla-wash`）とピーチのドットを使う。見出し・本文・ボタンの配色は共通パレットを維持する。

ルーム空間はユーザー指定（2026-10-28）の星空 `public/images/game/room-stars.webp` を使う。元画像は `SKYBOX5.png` で、絵柄・縦横比を保ったWebP。従来の木目は背景全面ではなく机の天板・厚み・四本の脚に使い、半透明の灰色の床に置く。床は初版の縦横それぞれ10倍に広げ、縁が画面に入りにくくする。机の脚の高さはステージ座標で164px。盤面と天板の間は1pxにして接地させ、木目は固定シードで生成した `public/images/game/wood-grain.svg` を面の材質として使う。天板だけを合成レイヤーにキャッシュし、同じSVGをカメラ移動のたびに描き直す負荷を抑える。星空の青は原画の色として扱い、メニューの配色には広げない。床の色は `--brand-room-floor`・`--brand-room-floor-edge`、暗い余白は `--brand-room-night`。立体物の陰影は机と床の接地を表し、ボタンやパネルに影を追加しない。

ルールから生成するサムネイル・OGPは、提供された大会レギュレーション画像を手本にしたポスター形式にする。採用可能な最後のフルーツを基準に、いちご＝淡いピンク、ぶどう＝淡い紫、めろん＝淡い緑、おれんじ＝淡いピーチを選ぶ（`src/lib/game/roomThumbnail.ts` の `roomThumbnailTheme`）。これはフルーツ識別のための画像内の色で、メニューのテーマ色には広げない。大きなフルーツ・ロゴ・ルール名・採用可能なフルーツの列・カードの扇形配置を使い、通常／拡張と制限時間を明記する。カードはそのルールで採用可能なものだけを選び、画像外に切らない。見出しはモッチーポップ、本文はZen丸ゴシック。ルーム名や招待の秘密は含めず、同じルールなら同じ画像を共用する。画像URLの版は `r5`。色・URL・実際の描画は `pnpm run test:room-images` で検証する。

## 形と文字

- 可愛さはロゴ・キャラクター・丸み・小さな動きで表現する。
- 盤面の縦書きラベルは「幼女／デッキ」「お菓子／デッキ」「お昼寝／場所」「除外／ゾーン」の言葉の区切りで列を分け、単語の途中で折り返さない。待機中・対戦中とも `BoardPieces.tsx` の `DeckStack` を共用する。
- 配色や読みやすさの修正では、配置・サイズ・装飾を同時に変更しない。必要な変更だけに絞る。
- 見出しの台紙・バッジ・帯を、文字の色修正のついでに追加しない。
- サイト共通で、見出し・メニュー名はモッチーポップ、本文・説明文・入力欄はZen丸ゴシック。漢字も実際に読み込まれることを確認する。新しいフォントを増やすときは既存の字体との相性を確認する。
- 画像自体の色は原画を尊重する。カードのフルーツ、PP、勝敗、警告など、意味を持つ色は識別性・ゲームルールを優先する。
- 紫・青・鮮やかな赤紫などを、新たな装飾用テーマとして増やさない。必要な状態色は役割を明確にする。

## 今回の適用範囲

トップページの紹介・各機能への入口・カードピックアップ・フッターと、ブラウザのテーマ色に共通パレットを適用した。デッキ構築やゲーム内の既存の意味を持つ色を、一律に塗り替える運用にはしない。今後、それぞれのUIを改修するときにも共通パレットを基準にする。

## カード画像・枠・動き（ゲーム画面）

カードゲームらしい繊細さを優先し、モダンなWebサイトの見た目にしない。下の規則には出どころを付ける。**【指定】** はユーザーが指定したもの、**【実装】** は指定を形にするときに決めた具体的な値・使い分けで、見直してよい。食い違うときは【指定】を優先する。

| 指定（日付） | 内容 |
| --- | --- |
| 2026-10-25 | カード画像を枠で囲ったり大きく丸めたりしない |
| 2026-10-25 | 回転のアニメーションを付けない。動かすなら上下か奥から手前 |
| 2026-10-25 | 枠はモダンなCSSでなく、カード画像の枠を手本にした植物的なオーナメント（SVG・コンポーネント） |
| 2026-10-25 | 小さいボタンは四角に少し丸みのある角か枠なし、大きいボタンはカード風 |
| 2026-10-26 | ルームの卓から対戦へ、盤面が横向きから回って自分の席が手前に来る |
| 2026-10-27 | カードの枠は複雑で太いので枠（パネル）向き。ボタンには細めの枠を作って使う |
| 2026-10-27 | ホバーで浮かせない。プレイヤーのアイコンは丸く切り抜く（重要）。カードの拡大表示は回転してよい |
| 2026-10-28 | 通常の操作はサイズによらず同じ角丸、押せない枠は角取り程度。席など場所を表すカード風の飾り枠は残し、縁と面のコントラストを弱める |

現在のゲームメニューは、操作に `--brand-control-radius`（8px）、パネルに `--brand-panel-radius`（2px）を使う。角丸をボタンの大小やホバー状態によって変えない。以下は2026-10-28の指定を優先した現行基準。

### カード画像

- カードの画像には絵柄の枠（黒いつる草の飾り枠）が描かれている。外側に縁取り・リング・色付きの枠・影の輪を足さない。
- 角丸をかけない（`border-radius` は付けないか、印刷の角程度の数pxまで）。円形・楕円に切り抜かない。
- 小さく見せるときも縦横比（2:3）のまま、そのカード全体を表示する。
- 【指定・重要】プレイヤーの識別表示（ルーム・ソーシャル・通知・プロフィール・アイコン選択）は例外として、選択した絵柄を丸いアイコンに切り抜く。デッキやカードそのものの表示にはこの例外を適用しない。

### 枠・パネル

- パネル・ダイアログ・席の札などの枠を、角丸の境界線と影だけのCSS（一般的なWebのカードUI）で作らない。
- カード画像の枠を手本にしたオーナメント枠を使う：細い外線と太めの内線の二重線、四隅のつる草と葉、辺の中央の菱形の飾り。部品は `src/components/shared/ui/ornament/OrnateFrame.tsx`（SVG）で、新しい枠もここに追加・調整する。
- 角は2pxの角取りにする。装飾の線は淡い面ではココア、暗い面ではクリームを40%の濃さで描き、文字・アイコンのコントラストは弱めない。
- ボタンは押せることが分かる形でよいが、枠と同じ場所で角丸の箱を重ねない。

### ボタン

- 【指定・2026-10-28】小さいボタンも大きいボタンも8pxの同じ角丸にする。メニューの操作にピル形・円形を増やさない。プレイヤーのアイコンと対戦中の丸い主要操作は既存の例外。
- 【指定・2026-10-29】チャットの入力欄・送信ボタンは完全な丸角を使う例外。操作と配置の詳細は[ルーム内チャット](social-rooms-design.md#ルーム内チャット2026-10-28)に集約する。
- 【実装】`OrnateFrame` は `as="button"`・`as="a"`・`href`・`role="button"` のとき、パネル用のつる草を描かず、固定角丸と淡い1pxの縁を共用する。`size` は余白の調整に使う。通常のCSSボタンは `--brand-control-radius`・`--brand-control-edge` を使う。席など、押せてもカード風の枠で場所を表すものには `appearance="panel"` を指定し、同じ部品のオーナメントを使う。
- 【実装】操作以外のパネルにはカード由来のオーナメントを残し、縁を薄くする。文字の色を一緒に薄くしない。
- 【実装】状態は面と線の色で示す（例：じゅんびOKは桜色の面、済んだら葉っぱの緑の面と線）。押すと2px沈む表現は使える。回転・左右の揺れは付けない。
- 【指定】ホバーで上に浮かせない（位置・大きさを変えず、面・線・透明度で示す）。
- 【実装】ボタンやメニューのパネルはフラットにし、段差の影・ぼかした影・反射・光沢を付けない。ロード画面に反射の走る演出を加えない。

ユーザー指定の例外として、対戦中のターン終了など主要操作には丸い装飾枠と静止した硬い光沢を使う。`RoundActionButton` に集約し、通常メニューへ光沢を広げない。操作不可は淡い単色面、相手ターンは中立色と文言で示し、ホバーで移動させない。

### アニメーション

- 回転させない。左右に揺れる・傾く・くるくる回るローディングは、左右対称の動きになって美しくないため使わない（静止した飾りの向きを決めるための回転は動きではないのでよい）。
- 動かすときは上下（浮く・弾む・下から現れる）か、奥から手前（小さく遠くから大きく近づく、または逆）にする。
- 【指定】例外：カードの拡大ビューはユーザー操作に応じて回転できる。構築・ルーム・図鑑で `components/shared/card/CardDetail.tsx` を共用する。
- 【指定】例外：ルームのテーブルから対戦に入るときは、盤面が横から見た向きから回って自分の席が手前に来る。動くのは床・机・盤面を一緒に映すカメラで、待機と対戦でシーンを作り直さない。席の札などの文字は常に正立させる。
- 待ち時間を演出のために足さない。`prefers-reduced-motion` では繰り返す動きを止める。

## フォントの共通定義

`src/app/fonts.ts` で見出し用・本文用のフォントを管理し、ルートレイアウトで全ページに読み込む。画面ごとに異なるフォント定義を追加しない。

`pnpm run fonts:generate` が固定コミット・SHA-256検証済みのGoogle Fonts原本からWOFF2を生成する（`predev`・`prebuild`でも実行）。トップのTSXに含まれる文字を各ウェイト1ファイルにまとめ、ゲームメニューの文字も専用ファイルにまとめる。ゲーム用の抽出対象は `scripts/generate-site-fonts.mjs` に集約し、`game/plaza/`・`game/launchpad/`・`game/home/` の分割部品はディレクトリから読み取る。残りの収録文字は重複のない最大64文字ずつの追加サブセットに分ける。別ページ・ユーザー名などに必要な漢字も削除せず、ブラウザが必要なサブセットだけ取得する。書体・ウェイト・字形・文字幅は維持する。

原本と生成キャッシュは `.next/cache/pplale-assets/site-fonts/`、配信用ファイルは `public/fonts/generated/`、生成CSSは `src/app/generated/site-fonts.css` に置き、Gitには含めない。`.next/cache` は `next build` でもVercel・CI・Dockerのビルドキャッシュでも保持されるため、2回目以降のビルドはサブセットを再生成しない。ライセンスは `public/fonts/*-OFL.txt` に保持する。初回生成にはネットワーク接続が必要。トップの文言変更は次の生成時に自動反映される。`pnpm run test:fonts` で文字の網羅性と字形・文字幅を検証する。

- `h1`〜`h6`、`legend`、タブは共通の見出し書体を使う。
- リンクやボタン内のメニュー名は `data-ui-title` で指定する。
- フォームや見出し内の補助文は本文用の書体を使う。
- 対戦盤面は `data-readable` で見出し用の装飾書体の適用から外す。カード効果・PP・HP・ダメージなどの文字や数値は、盤面で指定している読みやすい書体を使う。
