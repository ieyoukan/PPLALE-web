# 盤面エミュレータ

`pnpm run dev` → `/game/`。いちご・ぶどう・メロン・オレンジの幼女151種類・お菓子46種類、通常プレイアブル6種類と拡張プレイアブル3種類（しゅれい・いのまこ・ちょり）で対戦できる。メロンはぶどうまでの環境に足して使う（メロンだけの環境はない）。カード数は `src/data/yojo.json`・`sweet.json`・`playable.json` と実行定義を照合した値（2026-10-16）。今回の検証範囲は [検証記録](verification.md)。

## エディタでカード効果を試す

`/game/editor/` の「新しい盤面を作る」からカードを配置し、PPや能力などを設定する。メニュー →「この盤面で遊ぶ」→「両側を自分で操作する」で開始する。保存した盤面や共有コードからも開ける。

- カード追加画面では名前とフルーツで絞り込める。同名でもフルーツが異なるカードは別々に選べる。
- 場のカードを押すと、おにごっこの成功条件、かくれんぼの現在の有効状態、追加フルーツ、カード効果の喪失を設定できる。
- プレイアブルを押すと、Exスキルと回数、通常スキルの使用履歴、アイス／どんぐり／場を離れたもちだの数、通常ドローのスキップ数を設定できる。
- 対戦中のExスキルとどんぐりはプレイアブルのスキル画面から使う。自動発動のスキルは効果のタイミングで処理され、レンテの出目指定や手札誘発は選択肢が表示される。
- 編集結果は保存・再読み込み・共有コードを通して保持する。「✎ 編集」でその局面へ戻れる。

## リーサルパズル

ゲームメニューの「リーサルパズル」（`/game/puzzles/`）から、メロン初級①・②と中級①〜⑤の7問を選べる。一覧の見出しは「ロリの一手を極めるために」。問題は `src/data/lethalPuzzles.json` に提供された共有コードのまま保持する。中級③は訂正版コードで、相手の場の4枠目にメロンまめろん（`y_111`）がいる。

- 一覧には `/game/play/` と同じ `BoardTable` で描画した出題盤面の画像を表示する。説明文や数値の別表示で盤面を作り直さず、画像をタップしてその問題を始める。クリアした問題にはチェックが付く。
- 対戦中は「このターンで勝利」と「戻す」「やり直す」「一覧」の短いラベルを表示する。絵文字や飴の装飾は使わず、操作とクリア表示は線のSVGアイコンに統一する。クリア後は「次の問題へ」、再挑戦時は「一手戻す」を主操作として表示する。
- 自分の現在のターン中に勝利するとクリア。相手のターンが始まる前に決着するターン終了時の効果も含み、次のターンへ進むと再挑戦になる。
- 相手の手札も表向きで確認できる。相手が選択する反応は既存のCPUが処理し、相手ターンの対戦は続けない。
- 「一手戻す」「最初から」で何度でも挑戦できる。一手戻す操作は、自分の直前の選択と、それに続く相手の自動反応をまとめて戻す。
- クリア後は問題一覧へ戻るか、次の問題へ進める。クリア記録はブラウザ内に保存し、通常対戦・盤面エディタの保存データは上書きしない。挑戦途中の操作は保存せず、ページを再読み込みすると問題の最初から始まる。

盤面画像の再生成は、`pnpm run dev` を起動した状態で `pnpm run puzzles:images`。別ポートの場合は `pnpm run puzzles:images --url http://localhost:3100` とする。Playwrightが各共有コードから実盤面を開き、メニュー・操作ボタンだけを隠して1280×720のWebPを生成する。独立したブラウザを使うため、利用中の対戦データには触れない。`public/puzzle-previews/` と `src/data/lethalPuzzlePreviews.json` を一緒にコミットする。通常のビルド時には撮影せず、生成済み画像を配信する。画像の内容ハッシュをファイル名に含め、`Cache-Control: public, max-age=31536000, immutable` でブラウザ・CDNへ長期キャッシュする。変更時は新しいURLへ切り替えるため、古い画像のキャッシュと混同しない。Vercel固有の画像生成・ストレージAPIは使わない。`node --test tests/puzzle-previews.test.mjs` で問題コードと画像の対応・ハッシュ・寸法を確認できる。

## はじめる

- 盤面以外の画面は、左に縦のタブ（ロゴ、CPU対決 / バトル / リーサルパズル / カード / 盤面エディタ、プレイヤー名、サイトへ戻る）、右に選んだタブのページを出す（`home/GameMenu.tsx`、`app/game/(menu)/layout.tsx`）。背景はカードが浮かぶ夜空の画像 `public/images/game/menu-bg.webp`。ホーム画面は持たず、`/game/` を開くと CPU対決のタブになる。幅の狭い画面ではタブが上に横並びになる。
- CPU対決（`/game/`）は、CPUと対戦 / CPU同士を観戦、CPU の強さ（観戦では両側それぞれ）、ルール、双方のデッキを選び（初期手札やお菓子ポイントなどの進め方は固定で、変更欄はない）、「対戦をはじめる」で対戦画面 `/game/play/` に移る。ルールは双方のデッキに使えるカードの範囲で、2pick構築の最初の画面と同じタイル（`RulePicker.tsx`）で決める：フルーツは4つの環境（いちご／＋ぶどう／＋メロン／＋オレンジ。フルーツを選ぶとそれより前も入り、外すとそれより後も外れる）と、プレイアブルの通常（いつも使える）/ 拡張プレイアブル（ExP）。まだ対戦で動かせないものは「準備中」と出て選べない。前回の対戦のルールが最初から選ばれている。保存された対戦があれば「前回の対戦を続ける」が出る。
- バトル（`/game/battle/`）は人どうしの対戦の入口。左に「ルームマッチ」の説明と使えるかどうか（ルームの数などは出さない）、右に大きな扉を上から3枚（観戦する / ルームへ入る / ルームを作る）縦に並べ、選んだ扉の入力欄がその下に開く。「ルームを作る」（CPU対決と同じタイルで使えるフルーツと拡張プレイアブル（ExP）を、チェックボックスで観戦の可否を選ぶ）、「ルームへ入る」（6けたのルームID）、「観戦する」（観戦を許可したルームのID）がある。ルームのページではID・リンクのコピー、Discord 用の文面のコピー、X への投稿、端末の共有メニューで招待できる。仕組みは [game-design.md](game-design.md) の「ルームマッチ」。同じ端末でのふたり対戦は出さない（両側操作のモードは e2e テストなど保存データからは開ける）。
- 盤面エディタ（`/game/editor/`）は入口だけのページ（新しい盤面 / 編集のつづき / 保存した盤面 / コードから開く。共有リンク `?PPL1.…` はそのまま盤面を開く）。編集は対戦の盤面そのものの「編集モード」で行う（フォームの画面は持たない）。
  - 編集モードでは、空いている場の枠（＋）を押すとカード一覧が出て、選んだ幼女がそこに置かれる。手札の＋（手前は手札の右、相手は場の上）で手札に、山札・お昼寝場所・除外カードを押すと中身の一覧が出て加える・外す・山札の一番上にする、ができる。相手の手札も表向きで見える。
  - 場の幼女を押すと、盤面の横に攻撃 / HP の変化・受けたダメージ・能力・「出たばかり」「攻撃済み」などが出る。手札のカードはコストの変化と公開、プレイアブルを押すとプレイアブルの変更・お菓子と最大値・ターン数・最大PP・今のPP・スキルの残り回数・パンケーキ・呪文・「このゲームで手札から出したカード」。盤面のカウンターでも変えられる：「ターン数(+pp)」の ＜ ＞ でターン数（PPはターン開始時と同じく新しい最大まで入る）、「お菓子ポイント」の ＜ ＞ でお菓子。カウンターの名前を押すとそのプレイヤーの設定が開く。編集のパネルは右上の × で閉じる。
  - 場の幼女は持ち上げて別の枠へ動かせ、手札の幼女は場の枠へ運ぶとコストも効果もなしで置ける。変更はすぐ盤面に出て（演出なし）、メニューの「編集を一つ戻す」で戻せる。
  - 右の丸いボタンが「この盤面で遊ぶ」になり、両側を自分で操作するか、相手をCPUにするかを選んでプレイモードに移る。プレイ中は右上の「✎ 編集」（作った盤面と両側操作のとき）かメニューの「この盤面を編集する」で、今の盤面のまま編集モードに戻る。メニューの「最初の盤面に戻す」で遊び始めた盤面からやり直せる。
  - 右上のメニューは編集中は盤面エディタのメニューになる：盤面の名前、手番、先攻、最善手を調べる、共有コード（`PPL1.…`）とリンクのコピー、コードの盤面を開く、ブラウザへの保存、盤面を空にする。
  - 「最善手を調べる」は、このターンに勝てるか（詰み。不要な手を省いた手順）とさいきょうのおすすめの手順を、見えないカードも含めて調べる（`board/analysis.ts`）。編集中・作った盤面の対戦・両側操作で使える。作った盤面の対戦はCPUサーバーに送らない。
  - 実装：盤面への変更は core の `edit.ts`（`editGame`）、盤面の書き出し・共有コードは `position.ts`。UI は `table/EditMode.tsx`（編集中の表示・カード一覧）と `panels/EditPanels.tsx`。
- カード（`/game/cards/`）は「図鑑」（`/game/cards/zukan/`：幼女・お菓子・プレイアブル・トークンの一覧。押すと拡大と効果文）と「デッキ構築」（既存の `/build`）への入口。
- 対戦画面を直接開いても、準備した対戦がなければ `/game/` に戻る。メニューの「対戦をやめる」とリザルトの「ホーム」も `/game/` へ戻る。
- ロゴは `public/images/game/logo.webp`（提供された「お菓子争奪戦争 ぷぷりえーる」のロゴ）。
- デッキは、いちごのおためしデッキ、おまかせデッキ（ルールに合うカードからランダムに作る。対戦を始めるたび、ルームでは「準備OK」のたびに作り直す）、Google ログイン後は Firebase に保存したデッキから選ぶ。CPU対決の準備とルームのページで同じ（`DeckSelect.tsx`）。ルールに合わないデッキは選べず、「使えないデッキの理由」に理由が出る。選んでいたデッキがルールに合わなくなったら、合う最初のデッキに替わる。
- 幼女20枚、お菓子10枚を実際にシャッフルする。動物さんソーダとチャイは各種類1枚まで。使用できない保存デッキには理由を表示する。
- 盤面中央のダイスを振る。大きい目の側が先攻・後攻を選ぶ。同じ目なら振り直す。
- 光る山札を押して1枚ずつ引く。双方の初期ドローが終わったら、交換対象を複数枚選んで一括で引き直せる。双方が手札を決定すると先攻のターンを開始する。
- 初期手札は先攻3枚・後攻4枚。毎回、幼女 / お菓子のどちらから引くか選ぶ。初期ポイント12、各自の最初のターンは1PP。設定と裁定の詳細は `card-effect-rules.md`。

## カードとターン

- 画面下端に扇状の手札を重ねる。600px以下の幅では、各カードを押せるよう重ねず横に並べ、左右にスクロールする。カードを押すと、その1枚だけを大きく表示し、使用・配置・交換・閉じるを選べる。手札全体を広げるモーダルは使わない。
- 手札を選択して「場に出す」で空き枠へ配置する。選択後に空き枠を直接押して指定もできる。お菓子は「使う」。指やマウスで持ち上げて場へ運ぶこともできる。
- 使用可能な手札は緑に発光する。PPを消費し、効果に選択があれば場・手札・山札を直接押して指定する。その他の選択肢は盤面下に表示する。
- 攻撃可能な幼女を持ち上げ、光る相手にぶつけて攻撃する。カード選択→対象クリックでも同じ演出になる。防衛がいる間は、貫通がない限り防衛を持つ幼女だけ攻撃可能。挑発は選択するカード効果・スキルの対象を集中させ、奪う効果を無効化する。
- プレイアブルからスキルのモーダルを開く。効果・PP・残り回数をスキルごとの大きなボタンにまとめる。
- 「ターン終了」で、手札が10枚以上なら光る手札から除外するカードを選び、9枚まで整理してから相手に手番を渡す。先攻1ターン目を含め、通常ドローも空でない好きな山札を押して引き、引き終えるまでプレイやターン終了はできない。両方の山札が空なら補充せずに続行し、デッキ切れでは敗北しない。CPU は手札、スキル、攻撃、効果の選択を自動操作する。手札誘発で答えるかの判断には、偽ラグと同じだけ（1〜2.6秒）時間をかける。強さは「よわい」「ふつう」「つよい」「さいきょう」の4段階。「つよい」は勝ち筋の短い探索と局面評価、「さいきょう」は勝ち筋とターンの手順・相手の応手を探索する。探索には上限があり、最適手を保証するものではない（`packages/game-core/src/ai/levels/`）。

## 盤面の表現

- チェック柄と薄いロゴ、7枠×2列、左右の山札・捨て札を参照画像に合わせる。大型の VR 操作用球体は表示しない。
- 山札は残り枚数分のカード層を描く。ドローすると実際に1層減り、0枚なら空の枠になる。山札から手札へ移動して表になる演出を付ける。
- ポイントが初めて10以下・5以下へ下がると、その位置に小さい青いおはじきを置き、お菓子デッキを押して各1枚引く（強制で、引かない選択はない）。12→4なら2回発生する。回復して再度下がっても再発動しない。
- カード効果の演出は、core の `changesBetween` が出す変化の一覧から自動で作る（`board/presenters.ts`）。カードの移動（捨てる・破壊・除外・手札に戻す・奪う・山札に戻す）は元の場所から行き先へ飛び、能力値やキーワードの変化、回復、PP の増減はその場所に短いラベルで出る。カードを追加するたびに演出を書く必要はない（詳細は `packages/game-core/README.md` の「演出」）。
- カードの効果でダイスを振るとき（ぎってぃ）は、開始時と同じ3Dダイスを盤面の上で振り、出目とその意味（「3枚捨てる」など）を表示してから効果に進む（`table/EffectDie.tsx`。出目は core の `effectRoll` に記録）。
- 相手が盤面のカード以外を選んだとき（うぃまるの「1PP追加・2ダメージ」、フロートの「しない」など）は、その選択を「CPU：1PP追加・2ダメージ」のように中央上に表示してから処理する。手札誘発を「発動しない」と選んだときは、手札がわかるので表示しない。
- ぶどうのうぃまるを手札から公開して捨てるときは、自分・相手のどちらが使ってもカードを大きく表示し、「うぃまるを使った！」「お菓子ポイントの変動を無効化」を伝えてからお昼寝場所へ送る。CPUが自分のお菓子を食べるときも、自分の選択を待つ。手札のうぃまるを押すと発動し、「発動しない」で見送れる。
- 幼女やお菓子ポイントがダメージを受けた瞬間、その上に大きな赤い数字（白縁・平面、符号なし）をエフェクトと一緒にパッと約1秒表示する。幼女の攻撃によるダメージはクリーム色のトゲトゲした雲（ケンカの煙）、効果によるダメージは光。倒された幼女は、ダメージ表示のあと元の位置からお昼寝場所（除外なら除外カード）へ移動する（破壊された幼女は直前の位置に出す）。
- 幼女が受けたダメージは白い `−数字` のおはじき、追加最大PPは白い `+数字` のおはじきで表示する。
- コストや元の能力値はカード画像を使い、重ねて表示しない。能力の変化は白いおはじきで表示。キーワードも表示する。使用済みカードは傾けて暗くする。
- ロゴは `public/images/game/cafe-logo.svg` の描き起こし。原本との完全一致ではない。トークン（猫まんじゅう、ギガプリンなど）は `src/data/token.json` のカード画像で表示する。

## 両側操作・保存

- メニューは右上のボタンで開き、同じ位置の × で閉じる（横から出るパネルは同じボタンで閉じられる）。カードの拡大（場・お昼寝場所・相手の公開カードなど）とスキルの画面は、手札のカードを選んだときと同じ「閉じる」ボタンで閉じる（拡大は カードの右、スキルは右下。右上の × は出さない）。項目は対戦中に必要なものだけ：履歴、CPU一時停止、反対側を見る、一手戻す、最善手を調べる、この盤面を編集する、最初の盤面に戻す、形勢を表示する／隠す（CPU戦・両側操作・プレイヤー対戦・観戦）、対戦をやめる（ルームでは投了する・ルームを出る・観戦をやめる、リプレイ中は再生／一時停止・リプレイをやめる）。その対戦で使えるものだけ表示する。モード・強さ・デッキは準備ページで選ぶ。
- 観戦では CPU 1（奥・画面上）と CPU 2（手前・画面下）がダイスから最後まで自動で進める。両側の手札を表向きで表示し、カード・スキルの使用と選んだ対象を演出で表示する。メニューの「反対側を見る」で手札を見る側を入れ替えられる。
- 両側操作では手番に応じて盤面を反転。反対側を見ることもできる。
- 追加ドローは両側操作のスキル欄で実行する。カウンターでポイント / 追加PP、スキルの画面で現在PP、カードの拡大画面でダメージを調整できる（両側操作のとき）。通常の山札クリックは要求されたドローだけを行う。
- 「一手戻す」は直近20操作まで。対戦ログも表示する。
- 小さい常設の説明文やログ表示を置かず、山札の持ち上がり、光る対象、衝突演出で操作を示す。準備・詳細・ログはメニュー、スキルはモーダルで開く。
- 途中状態は初期ドローの途中もブラウザに自動保存し、再読み込みで復元する。このブラウザ内の対戦データを別端末へ同期する機能はない。ルーム対戦はサーバーで状態を管理し、同じブラウザに保存された席のトークンで再接続できる（[設計](game-design.md#ルームマッチオンライン対戦)）。
- 盤面はどの画面でも全体が収まる（下の「画面サイズと向き」）。

盤面文字には Yomogi の必要文字を同梱する。ライセンスは `public/fonts/Yomogi-OFL.txt`。

ダイスはあなた→相手の順に1つずつ振る。赤みのある焦げ茶色の6面ダイスをThree.jsの丸角メッシュで表示する。影は照明と実際の形状から描画する。自分のダイスは待機中に揺れ、直接タップすると跳ね上がり、回転して落下・バウンドする。CPUのダイスは自動で振る。画面中央には現在のダイス1つだけを表示し、止まった結果を少し見せてから次のダイスに切り替える。大きい目の側が先攻・後攻を選ぶまで初期ドローを開始しない。CPUが選択権を得た場合は自動で先攻を選ぶ。暗い背景でダイスに集中し、結果を表示した後で盤面に戻る。引き分けの場合も順番に振り直す。片方だけ振った状態も自動保存する。

ダイスに勝った側が人なら「先攻 / 後攻を選択」の画面で札を選び（ホバーで浮き、押すと選択状態になる）、「決定」で確定する。CPUが勝った場合はこの画面を出さず、CPUが自分で決める。

先攻・後攻が決まると、盤面をぼかした上に約3.2秒表示する（`table/OrderNotice.tsx`）。盤面と同じく上が相手、下が自分で、それぞれプレイアブルカード（切り取らず全体）と名前、「先攻」「後攻」の札を並べ、中央に VS を出す。自分の名前はログイン中ならユーザー名、未ログインなら「あなた」。CPU には強さを添える。

## レイアウトと色

- 右側のPP・ターン終了は対戦前（ダイス・初期手札）から表示し、最初のターンまでは押せない。途中で現れて盤面の幅が変わることはない。ダイスの「引き分け！」もダイスに重ねて出し、位置を動かさない。
- 準備ページのデッキ選択は盤面と同じ並び（上が奥＝相手、下が手前＝自分。観戦は上が CPU 1）。
- 対戦前後の画面（先攻・後攻、ゲームセット、リザルトなど）の色はロゴの配色に合わせる：クリーム `#fffdeb`、ライラック `#e7c3e2`、ピンク `#f4b0bb`、黄 `#ffef93`、緑 `#b3d788`、茶 `#a88667`（札やボタンの文字は濃い茶 `#6b4a3a`）。背景は白で塗らず、ぼかした盤面に黒の半透明を重ね、色は札・ボタン・見出しのアクセントに使う。

## 画面サイズと向き

- 対戦・ルームマッチ・リプレイの画面は、高さ720pxの固定の「ステージ」に配置し、画面に合わせて拡大・縮小する（`stage/GameStage.tsx`・`stage/stageSpace.ts`）。PCでもスマホでも盤面の配置は同じ。幅は画面の縦横比に合わせて16:10〜21:9の範囲で伸び、範囲外の余白は盤面と同じ木目で埋める。ノッチやホームバーの部分は避ける（対戦画面だけ `viewport-fit=cover`）。
- 縦向きは想定しない。縦向きの画面では、ステージを90°回して横向きに表示する（端末を左に倒すと正しい向きになる）。Androidなど対応する端末では、縦向きのまま画面に触れると全画面にして横向きに固定する。右下の全画面ボタン（自分のPPの下）でも切り替えられる。ページの全画面に対応しないブラウザ（iPhoneのSafari）ではボタンを出さない。iPhoneのSafariは向きを固定できないため、回転表示だけで対応する。
- ステージのCSSでは、画面の幅・高さを `vw`・`vh` ではなくステージを基準にした `cqw`・`cqh` で書き、画面サイズによる切り替えは `@media` ではなく `@container stage` で書く。ポインタの座標や `getBoundingClientRect()` は画面の座標なので、ステージ上に置くもの（ドラッグ中のカード、演出、マリガン、リプレイのシークバー）は `toStage`・`stageRect` で変換してから使う。
- 対戦画面ではピンチによる拡大、引っ張って更新、文字選択、長押しメニューを止める（引き出し画面のスクロールはできる）。場のカードはタッチで長押しすると拡大表示を開く（マウスでは右クリック）。押している間、カードが少しずつ大きくなる。

## 対戦の終了

決着がつくと「ゲームセット」→ 勝敗（勝ちは「勝利!!」、負けは「（勝った側の名前）の勝ち」。CPU戦なら「CPUの勝ち」）の順に表示し、タップするか数秒待つとリザルト画面に進む（`table/Finale.tsx`、`table/ResultScreen.tsx`）。再読み込みで終了済みの対戦を開いた場合は、リザルト画面から始まる。

CPU戦・両側操作・プレイヤー対戦・観戦では、形勢（どちらが有利か）の推移を対戦中に表示でき、リザルト画面にもグラフを出す（`useAssessment`・`AssessmentGraph`）。ルーム／フリーマッチの対戦中は、未公開の手札や山札の順番を使わない公開盤面の軽い評価を全員に同じ値で送る。ブラウザで探索し直さず、表示済みの局面だけを蓄積する。同じタブの再読み込みでは、対戦の固有IDを確認して保存済みの推移を引き継ぐ。

リザルトには、自分の操作で直前より形勢が12ポイント以上上がった場面を、上昇幅の大きい順に最大3件「好転」として表示し、グラフにはミント色のひし形を置く。連続した局面の評価が揃った場面だけを対象とし、相手の操作・ターン終了・悪手や疑問手と判定された操作は含めない。これはドローやダイス、新しく分かった情報を含む実際の形勢変化で、最善手との比較による手の良さの判定とは異なる。

計算済みの形勢はブラウザに保存し、再読み込みとリプレイで再利用する。直近の局面を先に評価し、過去の未計算部分を後から補う。悪手・疑問手の詳細解析は対戦終了後に行う。一手戻した後に違う操作をした場合は、その先の古い評価を破棄する。

ルームの履歴リプレイは、記録時のモデルによる軽い局面評価を各フレームに保存する（CPU戦の探索を伴う評価とは計算方法が異なる）。再生時に新しいモデルで再計算しない。履歴リプレイは対戦画面で再生し、保存された評価をリプレイのタイムラインとリザルトにも表示する（評価のない古い記録はタイムラインだけ）。再生中の形勢バーには、その時点までの評価だけを使う。

リザルト画面には、決着の理由（お菓子ポイントが0になった / 特殊勝利条件を満たした / 相手が敗北条件を満たした / 相手が投了した / 行動のないターンが続き、お菓子ポイントで判定）・ターン数（片方のプレイヤーが数えるターン。両者の合計ではない）・お菓子ポイント・先攻・CPUの強さと、次の操作を並べる。

| 操作 | 内容 |
| --- | --- |
| 使用デッキ 確認 | 使ったデッキのカードを枚数つきで一覧する |
| リプレイ | その対戦を最初から自動再生する。下から動画プレイヤーのような操作バーが出る（再生中は触らないと下に隠れ、画面に触れると戻る。一時停止中は出たまま）。再生／一時停止、前後のターンへ移動、形勢のグラフを兼ねたタイムラインのタップ・ドラッグでその場面へ移動、形勢が大きく動いた場面の目印から、その手の直前へ移動できる。キーボードはスペースで再生／一時停止、←→で一手、Shift+←→で一ターン。×かメニューで中断でき、終わるとリザルト画面に戻る |
| ホーム | ゲームのホーム（`/game/`）へ戻る |
| 再戦する | 同じデッキ・ルール・モード・強さで、山札を切り直して始める |
| 盤面を編集し直す / コードをコピー | 盤面エディタで作った盤面から遊んだときだけ出る。遊び始めた盤面を編集モードで開き直す／その盤面の共有コードをコピーする。このとき「再戦する」は「同じ盤面でもう一度」になる |

リザルトの見出しは勝った側の名前で「◯◯のかち!!」（自分が勝てばログイン中のユーザー名、未ログインなら「あなた」）。引き分けはない。CPU戦では自分のプレイアブル、両側操作と観戦では勝った側のプレイアブルを出す。

## 初期手札の一括交換

手札をタップ、ドラッグ、上下キーで上段の「交換する」枠へ移す（種類は問わない。`MulliganBoard.tsx`）。「交換」で画面を閉じて山札へ戻す演出を行い、続けてその枚数を盤面の山札から1枚ずつ引き直す。戻したカードは引き直す前に元の種類の山札へ戻してシャッフルする。新しいカードは山札から手札へのアニメーションで表示する。

## PPとターン操作

右側の操作欄は、相手のPP・ターン終了ボタン・自分のPPの順に縦配置する。PPは盤面の「ターン数（+PP）」と同じミント色・花模様・手書き文字で表示する。両者の現在PP／最大PPを表示し、自分の残りPPを緑の点灯で表す。盤面は操作欄の幅を確保し、デッキや場のカードを操作欄の裏に隠さない。

カードの拡大表示は外側の余白を8pxに減らし、操作ボタンの場所を確保した上で画面の高さ・幅に収まる最大サイズにする。手札は1枚だけの拡大を維持し、場や捨て札の詳細でもカードを大きく表示する。

公開したカードは通常の手札の端へ寄せ、間隔を空けてまっすぐ並べる。自分側は少し上、相手側は少し盤面側へずらし、「公開」の札を表示する。公開カードも手札の枚数に含まれ、選択やプレイは同じ操作で行える。相手の公開カードはクリックすると拡大できる。

カード効果で任意の手札を公開するときは、盤面の手札を直接押して選ぶ。選択カードは公開カードの位置に移して「公開予定」を表示し、そこで再び押すと通常の手札へ戻る。手札の少し上、中央に「公開を完了」を置き、押すと選択した手札だけをまとめて公開し、続きの効果を処理する。全枚選んでも自動確定せず、0枚でも完了できる。すでに公開済みのカードはそのまま残る。確定前のカードは相手に公開せず、選択状態は再読み込みしても復元する。

最大PPの上限は12。「使用できるPPを増やす」効果（どんぐり・前借り・さおちゃん）では、現在PPが最大PPや12を超えてよい。後攻の自分の5ターン目は、開始時の現在PPだけを追加で2増やし、白い+2おはじきで表示する。恒久的な増加がなければ表示は7 / 5で、回復上限や最大PPの条件は5のまま。残った現在PPはカードの有無にかかわらず相手ターン中も保持し、次の自分ターン開始時に通常の補充値へ置き換える（`core/cards.ts`・`commands/phases.ts`）。
