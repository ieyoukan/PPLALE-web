# カード効果の実装状況

ユーザー提供のルール・FAQを整理した参照文書は [ルール・裁定集](game-rules.md)。以下は現在のエミュレータの処理を記録したもので、提供ルールと未一致の部分を含む。文やFAQだけでは決めきれず仮の読み方で実装している箇所は [確認したいこと](open-questions.md) にまとめてある。

## 原文と実行処理

- 表示用の名前・能力値・日本語原文・画像は既存の `src/data/*.json` を維持する。
- 実行する効果は `packages/game-core/src/cards/` のカード ID ごとの `CardScript`（常在キーワードを含む）。スキルは `playables/skills.ts`。書き方は [game-core の README](../packages/game-core/README.md)。
- 原文を実行時に自然言語解析しない。操作・対象・数値・条件を TypeScript で明示する。
- 初期の宣言的 JSON 試案（`cardEffects.json` / `cardEffectSchema.ts`）は、実行定義を二重管理しないため削除した。

## ぶどう・オレンジの共通処理

- おにごっこは選択対象ごとに判定する。攻撃回避は攻撃時効果とリンネの手札誘発より先に行い、回避しても攻撃側は行動済みになる。対象が回避しても追加ドローなどは続ける。
- かくれんぼの能力と有効期間を分けて保持する。選択・攻撃対象から外し、有効中の防衛／挑発は対象集中に加えない。全体・ランダム効果には適用しない。奪取などで出し直したときは再発動する。
- 色おには発生元の幼女のフルーツタイプで判定し、全体・ランダム・通常攻撃のダメージも防ぐ。同タイプのお菓子やプレイアブルスキルには適用しない。効果破壊耐性はダメージ耐性とは別に管理する。
- レンテのExスキルは取得した回数を保持し、カードテキストの1d6を振るたびに任意で出目を選べる。ランダムな対象／カードの決定には使わない。
- リンネ・うぃまるの手札誘発、オレンジリンネの通常ドロースキップは、対象プレイヤーの選択を待ってから続ける。両側操作・CPU・ルーム対戦で同じキューを使う。
- 通常スキルの残り回数と使用履歴を別に管理する。あみのは残り回数だけを戻す。取得済みExスキルは場のカードが離れても保持する。
- 除外時効果はカード効果による除外だけで発動する。手札上限の整理では発動しない。もちだの破壊はお昼寝場所へ移さず除外し、場を離れた回数を記録する。
- 残りPPを相手ターンに参照／消費するオレンジカードがある場合は、その残りを保持する。次の自分ターンでは通常どおり補充値で置き換える。ターン終了時の手札整理はゆうひ等の終了時効果より先に行う。
- 保存データと盤面の共有コードに、追加タイプ・回避条件・かくれんぼの有効状態・効果喪失・Exスキル・各カウント・スキル使用履歴を含める。
- カードが場所を移るとき（手札から場に出るときを除く）、カード効果で得たものはリセットされる（ユーザー裁定）：能力値の変化・ダメージ・コストの変化・付いた能力・おにごっこ・タイプ・効果を失った状態・バリア・ポッキーのつながり・期限つきの行動不能。カードは最後にいた場所を覚えていて（`Instance.zone`）、動いていれば、次にカードを変えるとき（`touch`）か各処理の後（`syncZones`）に戻す（`core/movement.ts`）。手札から場に出るときは引き継ぐ（手札で強化されたもちだなど）。ソーダの「このゲーム中」のタイプは `lastingFruits` に持ち、移動しても残る。
- 「PPを回復する」（`gainPp`）は最大PPまでで、ダブルダガーが乗る。すでに最大PPを超えていれば減らさない。「使用できるPPを増やす」（`increasePp`：どんぐり・ストラの前借り・さおちゃん）は最大PPや12を超え、ダブルダガーは乗らない。
- 相打ちは同時判定：0になった幼女はまとめて破壊し、その中にいるほとり丸は同時に破壊された相手を数えない。破壊時効果の順は自ターン側から。
- 膠着の判定で、Exスキルと回数制限のないスキルの使用は「行動」に数えない。
- 攻撃のとき、CPU・ルームの相手が手札誘発（リンネ・うぃまる・メロンのあみの）を持っていなくても、30%の確率で1〜2.6秒待つ（偽ラグ、`useBoardAnimations.ts`）。
- 場を離れた幼女（破壊・手札に戻る・除外）は、場にいる間だけの状態を持ち越さない：失った効果（りくす）、効果で付いた能力とおにごっこ、かくれんぼの有効状態、バリア、ポッキーのつながり（相方の側も外す）。破壊時・除外時の効果は、離れた時点の状態で判定してから消す（`core/zones.ts` の `clearFieldState`）。奪われた幼女は場を離れないので引き継ぐ。
- 手札のカードの公開は、どの効果によるものでも `reveal`（`core/zones.ts`、カードからは `ctx.reveal`）を通す。「このカードが公開されたとき」（ぜんりょくおうえん☆ぷぷりえーる）は、公開ボタン・あみのの参謀・すいーつあーん・検索の「公開状態で手札に加える」のどれでも1回だけ発動する。
- 攻撃は、回避の判定 → 攻撃した側の攻撃時効果 → 攻撃された側の被攻撃時効果 → 手札誘発（リンネ） → ダメージ、の順に処理する。攻撃時効果で攻撃した幼女が場を離れたら、後続は行わない。
- 手札誘発の確認（リンネ・うぃまる・オレンジのリンネ）は、ルームでは質問文も選択肢も相手に送らない（`redact.ts`）。確認で止まること自体は伝わる。
- 「してもよい」支払いは、払っても何も起きないときは聞かない（ちょりの追加PP、うゆちの追加3PP、アイスの消費、ソーダの追加1PP）。ここあの献身は最大値で回復しないときは消費しない。お仕置き棒・おしおきなん！は、選べる幼女（かくれんぼ中を除く）がいなければ使えない。
- ぶどうのとここは、スキルの処理（対象の選択を含む）が終わってからかくれんぼを持ち、次の自分のターン開始時にその能力を失う。ようかんのターン終了は、味方の「場に出たとき」の反応が終わってから行う（`afterPlay`）。

## メロン・拡張プレイアブルの共通処理

- 期限つきの行動不能（メロンのちょり・オフティ二、プレイアブルのちょり）は、対象ごとに期限のターンを持ち、そのターンが終わると消える。場を離れたとき、ぶどうのりくすで効果を失ったときも消える。
- 1ターンに複数回行動できる幼女（メロンのふろんとさん）は、そのターンの行動回数を数える。再行動（メロンのえーりん）は行動済みを解除する。おにごっこで回避された攻撃、メロンのあみのに無効化された攻撃も1回に数える。
- 攻撃は、回避の判定 → 攻撃時 → 被攻撃時 → 手札誘発 → ダメージ → 破壊時効果などの残りの処理 → 攻撃終了時、の順。破壊時効果がさらに起こした効果や選択も終わってから、場に残ったえーりんの再行動を確認する。プレイアブルのちょりの反応スキルは、回避の判定の前に持ち主へ確認する（使うとダイスを振らず回避になる）。
- 攻撃力と体力の入れ替え（メロンのぎってぃ・ふろんとさん）は、現在の攻撃力と残りHPを新しい値にし、以前のダメージを消す。以後の全回復で、入れ替え前のダメージをもう一度回復することはない。
- 手札誘発のうち、メロンのぶらんちゃん（相手のプレイの打ち消し）の確認中は、プレイされたカードを両者に見せる。質問文と選択肢は相手に見せない。プレイアブルの反応スキルは公開情報なので、確認を隠さない。
- 「お菓子ポイントが回復するたび」（メロンのうぃまる・ももか）は、実際に増えたときだけ発動する。「奪う」で増えた分も数える。
- メロンのレンテが奪ったスキルは、プレイヤーごとに別枠で持つ。印刷どおりのPPで使い、使用履歴（ぶどうのしゅお・もなか）には数えない。
- スキルの回数は「上限」をエンジンが計算する（いのまこのパッシブで共通スキルが3回になる）。回数制限のないスキル（しゅれい）は残り回数を持たず、PP・MPだけで決まる。MPは初期3・最大20で、ルナレストアだけが回復する。
- 保存データと盤面の共有コードに、MP・行動不能の期限・行動回数・期限つきのフルーツタイプ・奪ったスキル・場に出たときの強化（ビデカメ）・捨てた幼女の数（しゅみあ）を含める。

確認の回答を待っている暫定処理：いっしょにおしゃしんは条件達成の自己申告後に双方ドロー。レンテの出目指定は1回のダイスにつき1回分だけ消費する。

## 現在の実装における「奪う」「減らす」「食べる」「回復」

| 表現 | core の処理 | 挑発 | パンケーキ |
| --- | --- | --- | --- |
| 奪う | 相手をX減らし、自分をX回復 | 無効化する | 一度防ぐ |
| 減らす | `points(..., 'reduce')` | 防がない | 防がない・回数も消費しない |
| 食べる | `points(..., 'eat')` | 防がない | 一度防ぐ |
| 回復 | `heal(...)` | 無関係 | 無関係 |

挑発は対象を選択するカード効果・スキルの対象を集中させ、奪う効果を無効化する。通常攻撃は防衛によって対象を制限する。挑発で奪う効果が止まる場合はパンケーキを消費しない。ポイントは0未満にならず、回復は現在の最大値まで。

「X個奪う」は相手をX減らし、自分をX増やす。回復は任意設定ではなく常に実行し、自分の最大値まで。挑発やパンケーキで無効化される場合は減少・回復の両方を行わない。以前の保存データの回復設定は読み込み時に除去する。

## お菓子の10・5

ユーザー指定の「初めて10になったら青いおはじきと1枚ドロー」を、10以下 / 5以下への初回到達として実装。各1回、回復後も使用済みを維持する。ドローは強制で、お菓子デッキをクリックして1枚ずつ解決する（辞退はできない）。その間は次の操作を待つ。12→4では2回発生し、各1枚を引く。比較はポイント変更直前と直後で行う。初期設定が10以下なら、10の通過によるドローは発生しない。

## 基本ルールの暫定値

| 項目 | 現在の実装 |
| --- | --- |
| デッキ | 幼女20 / お菓子10、動物さんソーダ各1枚 |
| 先攻・後攻 | 双方のダイスを順に振り、大きい目の側が先攻・後攻を選択。同値は振り直し |
| 初期手札 | 先攻3枚・後攻4枚、双方が並行して引く。1枚ごとに山札を自由に選択 |
| 初期手札の交換 | 戻すカードを種類に関係なく複数枚選んで決定し、元の種類の山札へ戻してシャッフルしてから、その枚数を1枚ずつ好きな山札から引き直す。双方の確認後に開始 |
| 対象が必要なお菓子 | 「相手の幼女1人に〜ダメージ」（猫 / 犬カフェオレ、コーラフロート、1枚目のメロンソーダフロート、動物さんソーダ X=2）は相手の場に幼女がいないと使えない。「自分の場にいる幼女1人を〜」（ケーキ、ドーナツ、シュークリーム）は自分の場に幼女がいないと使えず、ポッキーは両方に必要。全体が対象の効果は使える。スキルも同じで、うぃまるの3つとレンテの「うち来ない？」は相手の幼女が、りくすの「おしおきなん！」は直前の相手ターンにお菓子を食べた幼女がいないと使えない |
| 初期ポイント | 12、最大値も12 |
| PP | 各自のターン数 + 追加最大PP、上限12。開始時に補充、前借り分を控除。相手ターンの残りPPを扱うオレンジカードがある場合はその間保持し、次の自分ターン開始時に置き換える |
| 後攻5ターン目 | そのターンの使用可能PPに+2。白い+2おはじきで表示し、次のターンには残らない。カードやスキルが見る「最大PP」には、この+2も含める（`ctx.maxPp()`） |
| 手札上限 | 終了時10枚以上なら、本人が選んで9枚まで除外してから手番を渡す |
| 通常ドロー | 毎ターン、好きな空でない山札から1枚を手動ドロー。先攻1ターン目も含む |
| 山札切れ | 敗北なし。空の山札は選べず、両方空なら補充をせず続行 |
| 場 | 各7人、手札から出す場合は満員なら拒否 |
| 攻撃 | 各ターン1回、通常は登場ターン攻撃不可、幼女同士は同時ダメージ |
| 突撃 / 早食い | 突撃は登場ターンに幼女へ、早食いは幼女・お菓子へ攻撃可能 |
| 挑発 | 選択効果の元の候補に相手の挑発が含まれる場合、挑発持ちに対象を限定。奪う効果を無効化 |
| 防衛 | 防衛がいる間、貫通のない幼女は防衛持ちだけを攻撃可能。お菓子・非防衛への攻撃不可 |
| 貫通 | 防衛を無視してお菓子・他の幼女も攻撃可能。登場ターンの行動制限は別に判定 |
| 勝敗 | 効果の各処理後にポイント0を判定。引き分けはなく、同じ処理で両者が0になった場合は後攻側の勝利（膠着で同数のときと同じ扱い） |
| 膠着による決着 | ターン終了時に判定。そのターンにドロー・プレイ・幼女の攻撃・スキル使用がなければ1回と数え、どちらのターンかを問わず3ターン連続で試合終了。両者とも山札・手札がなく、攻撃できる幼女もスキルの残り回数もなければ即終了（「確定」の判定）。ポイントの多い側、同数なら後攻側の勝利。実装は `core/stall.ts` |

初期・通常ドローの山札選択、防衛、挑発、早食い、突撃、貫通はユーザー指定を反映。最新のユーザー指定により、挑発による対象集中は選択する効果に適用する。複数対象も最初の候補を固定し、1人の挑発を倒した後に一般の幼女を追加で選ぶことはできない。全体・ランダム効果には集中しない。1d6は6面ダイスを1回振り、1〜6の値を返す。

| 項目 | 提供されたルール・裁定 | 現在の実装／必要な修正 |

その他のFAQとの全件照合はまだ行っていない。上の表を、全FAQが実装済みであることを示す一覧として扱わない。

## 効果の解決順と追加の確認事項

- 使用履歴は対象カードの効果を組み立てた後に追加する。「既に」は今回を含めず、「このカードを含めて」は明示的に今回を足す。
- お菓子扱いでない裏メニューは、うぃまるのダメージ防止や次のお菓子の倍化を発動させない。
- おいしくなる呪文は使用回数を `sweetBoost` に加算し、次の対象お菓子を ×(1+回数) にする（2回で3倍、ターンをまたぐ）。倍化はダメージ / 回復 / 強化 / ドロー枚数に反映する。対象人数は増やさない。キーワードと単発の防止効果は重複させない。複雑な検索・破壊連動・支払いとの組み合わせは公式裁定を要確認。
- 対象がいない処理は不発になり、後続の処理へ進む。手札がなく捨てられなくても、かんらん / オフティ二の後続処理は行う。一方ドーナツは捨てた時だけ付与する。
- 効果のステップが新しく積んだ処理は、すでに待っている処理より先に解決する（そのステップの続きとして扱う）。破壊時効果は破壊の判定（各ステップの後）で積まれ、待っている処理の後ろに入る。
- 効果の処理中にHP0になった幼女は破壊する。同時に0になった幼女は、自ターン側を先に、各側は場に出た順（古いインデックス）に破壊し、破壊時効果もその順に解決する。攻撃前効果による破壊時能力の割り込み順など、資料にない細部は引き続き確認する。
- とここ・いのむーなど「味方が場に出たとき」の効果は、手札から出した幼女自身の登場時効果（ドローとその結果のバフを含む）を解決した後にかかる。効果で場に出た幼女にはすぐにかかる。
- ポイント変動がパンケーキで無効になっても、攻撃した幼女は「お菓子を食べた」扱いになる（りくす・おしおき対象）。防衛でお菓子への攻撃自体ができない場合は食べていない。
- ももかは山札の上から最初の店長／副店長を手札に加え、その後幼女デッキをシャッフルする。
- すいーつあーんは渡すお菓子がなくても PP を2回復する。
- みゅーとんは自分の場の幼女も選べる（出し直しになる。相手の場に幼女がいなくても、自分の場に他の幼女がいれば選ぶ）。相手に挑発がいれば相手の挑発だけを選べ、自分の場の挑発は関係ない。FAQ⑤-2 のとおりで、ユーザー確認済み。
- さら / みゅーとんは、破壊できなくても後続の複製処理を行う。今回のイチゴFAQ②-1で、じょんこを選んだ場合にも処理を続けると確認できた。
- まこぽにの +1/+1 は、場に出た時（手札からに限らず、さら / みゅーとんの複製も含む）のいのむーの有無で付与する。ユーザー裁定により、まこぽにを出した後にいのむーが出ても、いなくなっても増減しない。
- ストラの前借りは同一ターンおよび連続する自分のターンで再使用不可としている。
- 公開した手札は本人の手札に公開表示を付ける。CPU対戦の相手の公開カードも表示する。

追加の裁定は [ルール・裁定集](game-rules.md) に出典となるFAQと具体例を記録し、この文書で実装との対応を管理する。

初期手札の交換は、戻すカードを元の種類の山札へ戻してシャッフルしてから、その枚数を引き直す（上の表のとおり。戻したカードをまた引くことはありうる）。交換は1回だけで、確認状況はセッションに保存する。

## 決着の理由

対戦の決着は、どの経路でも `decideMatch`（`core/outcome.ts`）を通り、勝者と理由（`winReason`）を一緒に記録する。リザルト画面はこの理由から文を出す（`table/outcome.ts` の `reasonOf`）。

| 理由 | いつ | リザルト画面の文 |
| --- | --- | --- |
| `points` | 負けた側のお菓子ポイントが0になった | お菓子ポイントが0になった |
| `special` | カードの特殊勝利条件（ぶどうのいろは、ちむどんどん！）。カードからは `ctx.win()` | 特殊勝利条件を満たした |
| `defeat` | カードの敗北条件（メロンのもなか）。カードからは `ctx.lose()` | （負けた側）が敗北条件を満たした |
| `resign` | ルームで投了した | （負けた側）が投了した |
| `stall` | 膠着の判定 | 行動のないターンが続き、お菓子ポイントで判定 |

同じ処理の中で2つの理由が重なったときは、先に決まったほうが残る（カードの特殊勝利・敗北のあとで、お菓子ポイント0の判定が上書きすることはない）。理由を記録していない古い保存データは、負けた側のお菓子ポイントが0なら `points`、それ以外は `stall` として読む。

## 効果耐性で防いだときの表示

じょんこなどの効果耐性でカード効果のダメージが防がれたときは、その幼女の上にダメージの数字「0」を出す（ほかのダメージと同じ見せ方）。破壊が防がれたときは「無効」と出す。専用の大きな表示や待ち時間はない。挑発は、カードの挑発の表示だけで示す。無効化は対象への処理だけで、追加ドローや複製などの後続処理は継続する。

## ターン終了と保存データ

手札整理は`trimHand`、終了時効果は`endEffects`、手番の切り替えは`finishTurn`、次の開始時効果は`beginTurn`として順に処理する。手札上限による除外では捨てる効果を発動しない。整理の途中も保存・復元でき、CPUも同じ選択処理を通る。後攻5ターン目の追加PPは`turnPpBonus`で管理し、恒久的な`ppBonus`と区別する。旧保存データのPP上限・先攻ドロー・ライブラリアウト設定は取り除いて新ルールへ移行する。
