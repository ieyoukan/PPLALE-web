# デッキ一覧とOGP画像

2026-10-16 に実装と既存テストを照合した。結果は [検証記録](verification.md)。

## 一覧

- 自分の保存済みデッキを画像付きグリッドで表示し、スクロールで12件ずつ追加する。
- 更新日・名前の昇順／降順で並べ替えられる。名前・フルーツの組み合わせ・プレイアブルで絞り込める。
- フルーツは複数選択でき、デッキに含まれる組み合わせが選択内容と一致するものだけ表示する。いちごだけ選ぶといちご単色、いちごとぶどうを選ぶと両方を含み他のフルーツが入っていないデッキになる。フルーツ共通のお菓子は組み合わせに数えない。「すべて」または未選択ならフルーツで絞り込まない。
- 並べ替えや絞り込みでは未取得のデッキも順次取得する。データの読み込みと表示件数を分け、表示は12件ずつ追加する。
- プレビューは幅160pxの事前生成済みWebPをSVG内に並べる。日本語・英語の両方に対応し、画面近くにあるデッキだけ画像を表示する。一覧ではCanvasの描画・PNG変換・OGP APIの呼び出しを行わない。素材の更新はビルド時に行い、`pnpm run cards:thumbnails` でも再生成できる。
- 各デッキページの自動先読みを止め、一覧をスクロールするだけで大量のページ・メタデータを取得しないようにする。
- 共有リンクのコピー結果は押したボタンの文字と色で示し、3秒後に元の表示へ戻す。

## 共有用OGP画像

- OGP用カードPNGと一覧サムネイルはGit管理せず、`prebuild`・`predev`・`pretest:deck-images` で生成する。OGP用PNGは圧縮レベル9・適応フィルター・`palette: false` で保存し、減色を行わない。全208枚で縮小元画像との画素一致をテストする。約32.04MiBから約27.37MiBへ削減。生成スクリプトの更新も再生成条件に含める。キャプションとプロフィール背景は同梱素材として管理を続ける。

- OGP APIが呼ばれたときだけ生成する。デッキ一覧や構築画面は、OGPの生成完了を待たない。
- カード画像はサーバーに同梱したPNGを読み込み、縮小した画像も再利用する。ハッシュタグも生成済み画像を同梱し、OGP生成時には外部の画像やフォントを取得しない。ハッシュタグを変更したときは `node scripts/generate-og-caption.mjs` で画像を更新する（この更新スクリプトだけはGoogle Fontsへの接続が必要）。
- 画像の合成・PNG変換はSharpのネイティブ処理で行う。完成PNGは圧縮レベル6で配信し、縮小素材のメモリキャッシュは圧縮レベル1で作る。1つのサーバープロセス内で同時に生成するのは2件まで。同じカード構成への同時リクエストは1つの生成処理を共有する。
- 完成画像のメモリキャッシュにはプロセスごとに32MiB（32 × 1024 × 1024バイト）の上限を設ける。素材画像のキャッシュはこの上限に含まない。共有URLの署名が変わっても同じ構成の画像を再利用する。
- 署名付きURLを15分の区切りで安定させ、デッキの更新日時をURLに含める。更新後は別のURLになり、古い画像のCDNキャッシュを引き継がない。成功した画像のHTTPキャッシュは15分、署名自体の有効期間は既定1時間（`src/lib/ogSignature.ts`）。エラーは保存しない。`OG_IMAGE_SIGNING_KEY` が未設定なら、メタデータは共通の `/ogp.png` を使う。
- メタデータとデッキ画面は同じリクエスト内のデッキ取得を共有する。

初回アクセスやサーバー再起動後は、データの取得・素材の読み込み・画像生成が必要になる。初回も即時に返ることを保証するものではない。

## 検証用の既存テスト

- `pnpm run test:deck-images`：全カード素材でのOGP生成、同時リクエストの共有、キャッシュ、変更の反映、不正なデータ、日本語・英語のサムネイルを確認する。
- `npx playwright test e2e/saved-decks.spec.mjs`：画像が読めなくても初回12件を表示できること、全件へのスクロール、未取得のデッキを含む検索・並べ替え、複数条件の絞り込み、再読み込み、削除、共有、スマートフォン、英語表示を確認する。保存データの取得はテスト用データに置き換え、一覧コンポーネントは実装本体を使用する。実際の構築ページの表示とOGP APIの入力チェックも確認する。
